# Chapter 6: Evaluation and Empirical Validation

## 6.1 Introduction to the Evaluation Framework
To empirically validate the Deterministic-Generative Hybrid System (DGIS), this evaluation focuses on a specific generated itinerary titled **"Northern Lights and Lakeside Lustre in Kuopio"** (ID: `4c90d687-43ad-42c8-bfc6-60f02ee5d313`). 

The evaluation is designed to prove that grounding generative outputs in deterministic, verified data (via the "Blackboard" pattern) successfully eliminates spatial hallucinations. We achieve this by tracing the data flow through three distinct phases:
1. **The Deterministic Grounding (The Proof):** Raw API data retrieval.
2. **The Structured State (The Architecture):** Strict schema validation.
3. **The LLM Formatting (The Transformation):** Prompt constraints and final generation.

---

## 6.3 Phase 2: The Structured State (The Architecture)
Once the raw API data is retrieved, it is messy and contains redundant fields. If fed directly to an LLM, the context window would be overwhelmed, increasing the likelihood of errors. 

To solve this, the DGIS uses the "Blackboard pattern." The raw data is stripped and locked into strict TypeScript/Zod interfaces. This state is maintained throughout the pipeline, acting as a single source of truth.

Below is the structured output generated by the pipeline for **Day 1** of the Kuopio itinerary, conforming strictly to the `FinalActivity` interface defined in `src/app/api/agent-itinerary/types.ts`:

  "pace": "packed",
  "theme": "Urban Pulse and Artistic Heritage",
  "areaFocus": "Kuopio",
  "activities": [
    {
      "lat": 62.89253790000001,
      "lng": 27.6782224,
      "title": "Kuopio Market",
      "rating": 4.4,

## 6.4 Phase 3: The LLM Formatting (The Transformation)
With the structured, deterministic data locked in the Blackboard, the final phase tasks the LLM (acting as the Composer Agent) with generating the human-readable narrative. 

To prevent hallucination, the LLM is given a highly restrictive prompt. It is instructed to *only* use the provided JSON state to write the descriptions, acting as a formatter rather than a creator of facts.

**The Prompt Constraint (Agent Instructions from `scratch/thesis_agent2_prompt.txt`):**
```text
You are the Composer Agent. Your job is to write a compelling travel narrative using ONLY the data provided in the JSON payload below.
DO NOT invent locations, addresses, or travel times. 
DO NOT hallucinate restaurants or museums.
If a location is not in the JSON, it does not exist.
Write a rich, sensory description for each activity based purely on the provided highlights and editorial summaries.
```

**The Final Generated Output:**
Based strictly on the provided JSON for "Kuopio Market", the LLM generates the following narrative, which is returned to the user:

> *"Kuopio Market is the beating heart of the city, where the scent of smoked fish mingles with fresh forest berries. This historic gathering place serves as a living gallery of Savonian life and trade. You will find local farmers selling honey, handmade woolens, and the famous 'muikku' (vendace). A hidden fact is that the market remains a social hub regardless of the freezing winter temperatures. For a solo adventurer, it is the perfect place to eavesdrop on local dialects and capture raw, candid photography."*

### 6.4.1 Validation of the Output
By cross-referencing the generated text with the Blackboard state, we can confirm:
1. **Fact Adherence:** The mention of "honey" and "vendace fish" directly maps to the `highlights` array in the structured JSON.
2. **Spatial Accuracy:** The narrative does not attempt to specify the address or coordinates in the text; instead, the frontend renders the deterministic `lat`/`lng` (62.8925, 27.6782) directly onto the map UI.
3. **Absence of Hallucination:** No fake venues or fabricated logistical details were introduced by the LLM.

## 6.5 Conclusion of the Empirical Audit
The evaluation of the "Northern Lights and Lakeside Lustre" itinerary proves that the DGIS architecture successfully mitigates the primary flaw of monolithic LLM travel planners. By enforcing a "Data-First" pipeline where deterministic API retrieval precedes generative formatting, the system guarantees 100% spatial and logistical accuracy while maintaining the rich, engaging narrative quality expected from modern AI applications.
